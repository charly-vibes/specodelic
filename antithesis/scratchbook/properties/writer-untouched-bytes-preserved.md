# writer-untouched-bytes-preserved

## Invariant

For any successful `apply` edit, the emitted text differs from the source only
inside the replacement spans. Every other byte is identical: prose paragraphs,
`expr`/`predicate` cells not naming the id, CRLF terminators, trailing
whitespace, and table padding. An id edit may make a column visually unaligned;
it never realigns as a side effect (`width_padding_policy`).

## Why it matters

This is the property that makes the writer a *surgical* editor rather than a
re-serializer. It is also the mechanical realization of
`rename.prose_untouched_by_rename`: a rename must not touch rationale text that
happens to mention the old name as a word, and it must not normalize line
endings or whitespace in a way that pollutes diffs.

## Check mode

`assert`. Compare the source and emission byte-wise outside the known changed
regions; an equivalent oracle is "every byte unchanged except at the spans the
edit names".

## Public API / seam

`writer::apply` (`writer.rs:234-333`), `splice_replacements` (`:420-433`), and
the span family collectors (`:345-447`).

## Generator sketch

- Source with prose that mentions the old id as a plain word, not in `[[…]]`.
- Rows with padded cells, a transition table, and a property row whose
  `predicate` mentions the id in prose.
- CRLF variant.
- Apply a row rename and an Intent rename; diff source vs emission with a
  longest-common-subsequence or a span-aware comparator.
- Assert: prose bytes equal; line terminators unchanged; padding outside the
  replaced cell unchanged; table column widths not re-padded.

## Predicted at HEAD `c76e2b0c`

**GREEN.** The writer builds the result by pushing `source[cursor..span.start]`
verbatim, then the replacement, then the remaining source. There is no
formatting pass. Fixed tests cover prose, CRLF, and padding
(`tests/acset_writer_apply.rs:107-183`).

## What would make it red

- A future change that routes emission through a Markdown formatter or
  re-serializes a table row.
- A replacement span that covers surrounding padding (span-coherence failure
  would surface first as `spec.span_failure`, but an over-wide span that still
  matches the parsed value cannot happen without a parser change).
- CRLF normalization in `rewrite_text`'s fallback path for unparsable files:
  the fallback explicitly preserves the original terminator, so a regression
  there would be caught by this property if the corpus includes prose files.
- A width-padding policy change that realigns columns after an id length change.

## Existing instrumentation

Partial: three fixed tests. No generated byte-diff oracle across families.
`tests/acset_writer_identity.rs` has a CRLF identity test, which covers the
no-edit half.

## Assumptions and Open Questions

- None that change the invariant.

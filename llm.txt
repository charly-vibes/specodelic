# specodelic

> A specification format and toolchain for AI agents — plain markdown with a closed four-table schema, checked by a self-hosting linter.

## What It Does

specodelic specs are markdown files: YAML frontmatter (`id`, `kind`, one EARS
`statement`) plus three fixed tables — Constraints, Model, Properties. The
linter never parses prose; all semantics live in the structured rows, so prose
stays free. Every structured `[[wiki-link]]` must resolve; every constraint
needs a deriving property; every model transition needs a guard.

- **Four layers** — frontmatter, Constraints (invariant/effect), Model
  (states + guarded transitions), Properties (deriving, with generator +
  predicate).
- **EARS statements** — the frontmatter `statement` must match one of the
  five EARS patterns.
- **Closed kind sets** — row `kind` values are closed sets enforced from the
  same constants that document them.
- **Reference typing** — what a `[[link]]` in each column may point at.
- **Pipeline** — lint → compile (TOML + proptest + TLA+) → model-check
  (embedded stateright) → verify (proptest execution).

## Key Commands

```
spk lint          # the gate; findings self-describe (rule_id + semantics)
spk graph         # reference graph, dangling detection, fan-in/out
spk new           # scaffold that teaches its own tables
spk compile       # three artifacts, total or labeled failure
spk model-check   # bounded exhaustive model checking
spk verify        # execute the property scaffolding
spk parse <file>  # parsed Spec IR as a json envelope (syntax-only)
spk doctor        # workspace health check
spk explain       # explain a rule or finding
```

## Self-Hosting

The format corpus (`specs/`) is written in the format and linted by the tool
itself (`just lint-specs`). Engineering truth (openspec) shares the same
grammar via the dual-format protocol.

## Installation

```bash
cargo install specodelic
```

# specodelic

> **`llm.txt` — repo-root machine summary, regenerated by
> `scripts/stamp_llms.py`; do not hand-edit — run `just
> stamp-artifacts`.** Content is derived from the repo-source
> `llms.txt` (identical body). The deployed, version-stamped copy
> lives at https://charly-vibes.github.io/specodelic/llms.txt — cite that one when the version matters.

> A specification format and toolchain for AI agents — plain markdown with a closed four-table schema, checked by a self-hosting linter.

## What it is

specodelic specs are markdown files: YAML frontmatter (`id`, `kind`,
one EARS `statement`) plus three fixed tables — Constraints, Model,
Properties. The linter never parses prose; all semantics live in the
structured rows, so prose stays free. Every structured `[[wiki-link]]`
must resolve; every constraint needs a deriving property; every model
transition needs a guard.

The CLI binary is `spk` (crate: `specodelic`).

## Core concepts

- **Four layers** — frontmatter, Constraints (invariant/effect),
  Model (states + guarded transitions), Properties (deriving, with
  generator + predicate).
- **EARS statements** — the frontmatter `statement` must match one of
  the five EARS patterns.
- **Closed kind sets** — row `kind` values are closed sets enforced
  from the same constants that document them.
- **Reference typing** — what a `[[link]]` in each column may point at.
- **Domain packs** — a workspace extends the format via `kind: profile`
  manifest specs (no config, no registry; lint discovers packs by corpus
  scan). Four ship in-repo: `data.lineage`, `numeric.predicates`,
  `empirical.registry`, and the `bioimage.data` D6 pilot (first
  cross-pack `## Requires`). Contract: [[packs]].
- **Pipeline** — lint → compile (TOML + proptest + TLA+) →
  model-check (embedded stateright) → verify (proptest execution).

## Command surface

- `spk lint` — the gate; findings self-describe (rule_id + semantics)
- `spk graph` — reference graph, dangling detection, fan-in/out
- `spk new` — scaffold that teaches its own tables
- `spk compile` — three artifacts, total or labeled failure
- `spk model-check` — bounded exhaustive model checking
- `spk verify` — execute the property scaffolding
- `spk doctor` / `spk explain` / `spk init` / `spk feedback`
- `spk parse <file>` — the parsed Spec IR as a json envelope (syntax-only,
  one file per invocation; for fleet consumers integrating over the binary)
- `spk rename` / `spk merge` / `spk refactor` / `spk orchestrate` (specced, stubbed)
- `spk migrate <file>` — wrap an openspec delta into the dual-format skeleton
- `spk archive-companion <CHANGE_ID>` — archive an openspec change preserving its dual-format layer
- `spk hooks install|uninstall` — wire/unwire the dual-format lint gate in the hook chain

## Self-hosting

The format corpus (`specs/`) is written in the format and linted by the
tool itself (`just lint-specs`). Engineering truth (openspec) shares
the same grammar via the dual-format protocol.

## Installation

```bash
# macOS & Linux (curl — resolves the latest release automatically)
V=$(basename "$(curl -fsSLI -o /dev/null -w '%{url_effective}' \
  https://github.com/charly-vibes/specodelic/releases/latest)" | sed 's/^v//')
TGT="$(uname -s | tr '[:upper:]' '[:lower:]')_$(uname -m | sed 's/^x86_64$/amd64/; s/^aarch64$/arm64/')"
curl -fsSL "https://github.com/charly-vibes/specodelic/releases/download/v${V}/specodelic_${V}_${TGT}.tar.gz" | tar xz
chmod +x specodelic spk && sudo mv specodelic spk /usr/local/bin/

# Or via Cargo
cargo install specodelic
```

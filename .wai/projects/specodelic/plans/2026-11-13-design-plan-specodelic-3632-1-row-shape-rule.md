DESIGN+PLAN — specodelic-3632.

(1) ROW-SHAPE RULE. New lint rule id linter.row_shape_closed, family linter-schema_shape (src/lint/rules.rs lint_schema_shape_family), semantics: every Constraint/Property/State/Transition row's field set must be exactly its kind's base fields plus the typed reference columns the Reference Typing table declares — an undeclared column is a finding. Field-set source of truth: the reference-column half is read LIVE from the Schema-as-data (crate::acset::schema::canonical().morphisms grouped by source object: Constraint->traces_to,supersedes,satisfies,observes,uses; Property->derives_from,supersedes; State->emits; Transition->guard,from,to), never a hardcoded per-field list; the base-field half (Constraint{id,kind,expr}, Property{id,kind,generator,predicate}, State{id}, Transition{id}) is a per-kind constant table in src/lint/row_shape.rs mirroring openspec/specs/kinds/spec.md's four *_row_shape constraints (same precedent as guide::CONSTRAINT_KINDS mirroring the corpus's closed sets). Intent/frontmatter is out of the rule's scope (kinds.intent_row_shape allows optionally-declared frontmatter keys such as checked_against_core). Corpus documentation: the rule enforces kinds.md's existing constraint_row_shape/state_row_shape/transition_row_shape/property_row_shape — cited by the rule_semantics string, by a new Checker-Ownership row entry in openspec/specs/specodelic/spec.md (linter-schema_shape.md now owns kinds.constraint_row_shape, kinds.state_row_shape, kinds.transition_row_shape, kinds.property_row_shape) and by a Note in openspec/specs/kinds/spec.md. No new corpus constraint/property row (the corpus already states the rule; inventing a rule the corpus cannot explain is forbidden).

(2) ROW-SHAPE DETECTION. A table row's column set is already visible in the parse model: Constraint/Property rows carry every header in Row.cells; Transition rows carry every header as a cell_spans key; State rows are bullets whose optional tail is parsed by parse_state_bullet (src/spec.rs). The one gap: a State bullet's tail is currently swallowed as 'emits' whatever it says, so an extra State field ('kind') is invisible. Fix in the parser (src/spec.rs): parse_state_bullet recognises a named tail 'name: value'; a name other than 'emits' becomes an extra cell on the State row (the corpus only uses '(emits: ...)' tails, so no corpus text changes). The rule then rejects any column outside the allowed set.

(3) REVISION-DIFF SEAM. New module src/lint/revision.rs, public API: specodelic::lint::revision::check_pair(prior_text: &str, current_text: &str) -> Result<Vec<RevisionFinding>, String> plus the diff shape IdSetDiff { removed, added, new_revision_heading }. It parses both texts with spec::parse_str and computes the 𝒦-governed id-sets of append_only_variants: the States variant-table ids, the Constraint rows' kind value-set, the Property rows' kind value-set, and the Reference Typing table's field set (read from the doc-side table when the file carries one). A member REMOVED from any governed set is a finding (S(r) ⊆ S(r'), 'no member removed or renumbered'); a member ADDED with no new '## Revision N' heading in the current text is a finding ('grown only under a new Revision heading, never silently'); a member added WITH a new Revision heading passes. Revision headings are read from the parser (Spec::revision_headings, src/spec.rs, skip_serializing so spk parse --json stays byte-stable). Both the kinds subkind row and the specodelic shrink row call this one seam.

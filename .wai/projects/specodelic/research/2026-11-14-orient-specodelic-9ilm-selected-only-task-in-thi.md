ORIENT: specodelic-9ilm selected (only task in this run). Repo charly/specodelic, main at 24bbc00, clean. Observation (8mta RO5U M4): Atomic::Resolves(m) in src/kernel.rs is morphism_values(m).iter().all(|(_,t)| t.is_some()); acset instance vectors contain only stored link values, so a corpus with no values for m (e.g. no uses edges) satisfies all() vacuously and evaluates Verified. Decision: this is the intended reading — resolves(m) is a universal over the relation's defined values; no values means no counterexample. Unknown is reserved for claims the evaluator cannot discharge (unresolvable literals, traversal failures), not for a discharged vacuous universal. Changing it to unknown would make the atomic unusable in corpora that legitimately do not exercise a relation. Document the vacuity explicitly in a decision note + kernel.md Notes, and pin it with a test. No lint advisory in v1 (a claim over an unexercised morphism is a modeling smell, not an error; follow-up only on dogfood friction). Out of scope: no behavior change, no new atomic, no grammar change.

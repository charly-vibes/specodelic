green		 spk graph can report satisfies-edges into a pack's extension_point (the contract-wiring spike already exposed fan-in), so *some* negotiation falls out for free — but sections/kinds/checkers are invisible to it.

10-invariant-preservationPreserved by discipline only. Nothing checks that a pack narrowing an existing set or reference typing is a bug — the append-only law applies to the format's own tables, not to pack claims.
red		 Enforceable: a checker validates manifests against the base format_revision (a pack may only add, never narrow — append_only_variants applies to pack manifests themselves). The invariant becomes lintable, not conventional.
green		 Enforced at row level only (ref_kind_compatible, reachability); nothing prevents a pack narrowing a kind set — the edge has no opinion.
red		 Weakest: manifest preservation rules are enforced by code reading config, not by the format's own lint discipline. Violates the self-hosting ethic every vendor preserved (and specodelic's own founding pattern).

green		 Conformance edges into a pack's extension_point render in spk graph and get blast-radius/fan-in treatment (the contract-wiring spike exposed fan-in). Everything sections/kinds-level stays invisible to discovery surfaces.

13-pack-revision-compatNothing tracks which revision a pack extends. Mistral-science had to infer "Revision 13" from a table mention and flag the guess in its own provenance; grok-bioimage explicitly deferred all Revision work. Drift between pack and corpus revision is undetectable.

green		 The edge carries no revision information; a satisfies row cannot state which revision its target contract was published under. Conformance checks silently compare across revisions.
red		 The manifest schema can carry a revision field and the CLI can compare it against the corpus mechanically — but nothing in-corpus checks the claim, so a stale manifest is trusted config until code says otherwise.

14-section-collisionUnmanaged. The collision is not hypothetical: mistral-science and mistral-bioimage both proposed `## Data` with different schemas (id/kind/schema/produced_by vs name/shape/dtype/range/units). Adopting both as-written yields two incompatible meanings for one section header.
red		 The manifest registers section names, so a checker can detect the collision at enable time. Whether section names are pack-namespaced (like kinds) or registry-claimed first-come is open sub-question D2 — either way the collision becomes detectable instead of silent.
yellow		 Out of reach: a row-level edge cannot see section headers, so colliding section declarations from two packs go undetected.
red		 The manifest registry detects name collisions mechanically at load time — the cheapest detection of the four approaches, though the check lives outside the corpus's own lint discipline.

# Decision: pre-commit sweep policy — specodelic-dz4 remediation (b)

- **Date**: 2026-10-05
- **Ticket**: specodelic-dz4 (P2 bug, parent; incident commit e7bb19e)
- **Status**: **ADOPTED — policy-first + drill-lock interlock** (children
  specodelic-do8 and specodelic-2g1 carry the implementation; no separate
  hook ticket is filed for (b)).

## Incident decomposition

The e7bb19e incident had two independent failures; (b) addresses only the
first:

1. **Staging sweep**: a concurrent session staged and committed another
   session's in-flight working-tree edits (6 legit rebinds + the
   seeded-violation poison `no-tag-drift.toml → no_such_test_exists_xyz`).
2. **Poison passed the hook**: the committing session's pre-commit ran
   structural-only `ah check`, which cannot detect a seeded violation.
   *Already remediated* — the semantic guard landed as `guard-espectacular`
   (7fca7ef); this is not (b)'s scope.

## Options considered

- **(B1) Hook-side authorship detection** — pre-commit refuses commits
  containing files the committer "did not author". **REJECTED**: git has no
  per-session authorship signal for staged or working-tree files; every
  heuristic (mtime windows, editor lockfiles, per-tool worktree manifests)
  is spoofable, racy under exactly the concurrent-session conditions it
  targets, and would produce false positives for legitimate human
  multi-window work. Not implementable without a claims/ownership registry
  no tool here provides.
- **(B2) New hook installed outside the beads chain** — **REJECTED**:
  AGENTS.md hard blocker — beads owns `core.hooksPath` (`.beads/hooks`);
  the `.beads/hooks` shims are regenerated by beads tooling, so edits there
  are clobbered, and claiming hooks elsewhere is the pretender-class
  violation the sibling-blockers guard exists to prevent.
- **(B3) Policy-only** (agents check `git status --short`, stage only
  files they authored, attribute messages to what the diff contains) —
  **PARTIALLY ADOPTED** as child specodelic-2g1, but policy alone failed
  once already and has no mechanical backstop.
- **(B4) Drill-lock interlock** — **ADOPTED** (mechanical half). Gate
  drills (ah check seeded-violation runs, guard-espectacular poison files)
  hold an advisory lock while live; a hook-side guard refuses
  commit/push while a live drill lock is held. This makes *drill state*
  mechanically uncommittable during a drill, closing the actual
  poison-injection vector of e7bb19e, without needing authorship metadata.

## Decision

1. **The mechanical interlock (B4) is the only hook-side change adopted
   for (b)**, and its implementation belongs to **specodelic-do8** (its
   meter already names the pre-commit check). It MUST be implemented as a
   check inside `scripts/guards/` wired through `lefthook.yml`
   (`pre-commit` + `pre-push`) and mirrored in `just ci` — the sanctioned
   chaining extension point per the lefthook.yml header and the
   espectacular-adoption decision (sibling-blockers updated in the same
   commit as any wiring). No edits to `.beads/hooks` shims; no new
   `core.hooksPath` claims; no `.git/hooks` writes.
2. **The residual sweep risk (foreign non-drill files) is accepted as
   policy-mitigated** via specodelic-2g1's standing instruction. Mechanical
   authorship detection is out of scope until a repeat incident
   demonstrates a concrete, non-spoofable signal; if that happens, the
   escalation path is a session-lock/manifest design call, not a hook
   heuristic.
3. **No separate ticket is filed for (b).** Parent specodelic-dz4 closes
   when its children (do8, 2g1) close — per its 2026-10-04 note — or on
   owner instruction.

## Constraints that survive

- beads owns `core.hooksPath`; lefthook.yml is the only sanctioned
  extension point (AGENTS.md, `scripts/guards/sibling-blockers.sh`).
- Guard checks must print a remediation hint and exit nonzero on
  violation (house style, matching `sibling-blockers.sh`).
- Lock staleness handling (crash-orphaned locks) is do8's design detail;
  the guard must not wedge the repo on a stale lock.

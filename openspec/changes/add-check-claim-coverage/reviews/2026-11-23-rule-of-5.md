## Findings

### CORR-001 — CRITICAL — `unchecked` conflates "no evidence" with "evidence out of authority"
`design.md` D2; `specs/check/layer.md` `claim_coverage_listed`

D2 assigns `unchecked` to "a claim with no evidence row". `check.no_foreign_authority`
forbids reading sibling bindings, and the sibling surface is large and green (M5/M6:
301 contracts, 202 reachable claims). A `check` run would therefore report claims as
`unchecked` that **do** have external evidence — and because the section never gates,
the conflation is silent.

Grounding: `dont` keeps the two absences apart — `src/model.rs:5`
`Status {Unverified, Verified, Doubted, Ignored, Locked}` (never verified) versus
`src/main.rs:2725` evidence outcome `"unchecked"` (evidence present, not checkable),
rendered as `skip` at `src/main.rs:1763`.

*Fix applied:* D2 now defines `unchecked` as "no evidence from this run's producers"
and D10 carries the matching scope statement; the layer constraint says the same.

### CORR-002 — HIGH — no fold rule for a claim carrying several rows
`specs/check/spec.md` ("exactly one class"); `design.md` D5
*TypeSafe: verified 0.93.*

`src/check.rs:51-53` emits property rows **and** model rows for one judged file; the
model row names the claim directly (`verify:model:<claim-id>`, `src/check.rs:123`),
the property row names a **property** (`src/check.rs:60-70`, `row.claims` holds the
property id). Two conforming implementations would disagree on a claim's class.

*Fix applied:* D8 (placement) and D9 (fold + precedence) added; the delta and the
layer constraint now state the rule, not only the outcome.

### CORR-003 — HIGH — the section's materialization site is unspecified
`tasks.md` §4–§5; `specs/check/layer.md` `report_interop`
*TypeSafe: verified 0.32 → REVIEW_REQUIRED.*

`report_interop` freezes "same schema version, field set, row keys". A coverage field
added to `AuditReport` (`src/audit.rs`) changes the field set and would touch
`spk audit` too.

*Fix applied:* D10 pins the section to the **check envelope**; `AuditReport` and its
schema version stay untouched; `tasks.md` §0 names the site and adds a RED test.

### CORR-004 — MEDIUM — four of the six reused classes have no producer path
`design.md` D2. `stale` needs `--before`; `new` needs `--before`; `binds_nothing` only
appears for vacuous units; `contradicted` needs a failing run. D10 now tabulates which
producer yields each class.

### CORR-005 — MEDIUM — the investigation's own baseline figure was wrong
The pre-review analysis reported "19% of claims placable, 49 of 50 files ~100%
unchecked". The 19% figure was right for **check-internal** producers (M7) but the
"49 of 50 files" part was not: the sibling surface reaches 202 claims (M6) and the
files are not uniformly empty. Both numbers are now in the proposal's "Why", labelled
by producer.

### CORR-006 — CRITICAL (new) — the change's self-hosting fixture does not exist today
`design.md` D7; `proposal.md` "Baseline, stated so the first run reads honestly"

The proposal states: "a first report lists most claims as `unchecked` and still exits 0".
Measured (M9, M10): **0 of 50 corpus capability files can be judged by `spk check`
today** — 19 refuse at `artifact_gate` because `src/check.rs:242` calls the
corpus-less `conform::gate` (the corpus-aware `conform::gate_in_corpus` is wired for
`spk conform` at `src/commands/corpus.rs:888-925`, not for `check`), and 31 refuse at
`verify_model` for an absent model-check report. Of the 4 capabilities whose verify
gate could pass, only `compile` has executable properties at all (M8/M9: 470 of 572
properties are `todo_predicate!` stubs).

So the section's first appearance is one capability's worth of coverage, and the
"still exits 0" baseline cannot be reproduced on this corpus until the gate is wired.
Filed as a bead; recorded here as a **precondition** of the change.

### DRAFT-001 — HIGH — the "5 of 643" figure is true but read narrowly
`proposal.md` "Why"; `design.md` D1

Reproduced exactly (M3) — but only for the **Constraints** table. The same measurement
over Properties is 296 of 613 (M4), and 301 of 643 contract files name a property of
their own capability (M5). The corpus explains it: `openspec/specs/compile/spec.md:264`
is `#### Scenario: precondition_violation_rejected` with
`- **VERIFIES** [[compile.precondition_violation_rejected]]` — **scenarios are titled
by property id**, so the external surface speaks in properties.

*Fix applied:* the proposal's "Why" now carries M3/M4/M5/M6 side by side, and D8 makes
the property→claim hop explicit instead of leaving it to be invented at implementation.

### DRAFT-002 — HIGH — no design section defines the placement rule
D3 and D5 presuppose it. *Fix applied:* D8.

### DRAFT-003 — MEDIUM — "invariant" narrowing unexplained
44 non-invariant claims (39 effect, 2 advisory, 3 extension_point) are excluded with
no rationale. *Fix applied:* D2 states the narrowing and why.

### EDGE-001 — HIGH — exit 0 with everything unchecked reads as a pass
`design.md` D4. Grounding in both directions: `dont`'s `prime`
(`src/main.rs:4856-4960`) counts `unverified` and exits 1 only on `blocking`
(doubted) — absence visible, contradiction fatal, the same shape as D4; while
`espectacular` gates the opposite way (`src/check/structural.rs:1-16`: "every finding
this module emits blocks execution for its scenario", with `no-tests-declared` as a
finding kind). *Fix applied:* D4 now names the `dont` model as the grounding and the
`espectacular` divergence as deliberate; `tasks.md` §4.3 binds the count to the
verdict line.

### EDGE-002 / EDGE-003 / EDGE-004 — MEDIUM
`bind:` rows are claim-keyed but vacuous (`src/audit.rs:629-641`) — D9 states their
precedence; the residual bucket holds rows, not claims — D8/D9 say so; `check` judges
one file per invocation, so the file prefix is constant — D1/D10 decide the prefix
lives in the section's keys.
